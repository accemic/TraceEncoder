# Gate evidence — what is versioned and what is not

All gate output used to live in `bld/`, which is gitignored. That is
fine for a transcript and wrong for a verdict: on 2026-08-05 a re-mint
overwrote the one file a closed package had been measured against, and
the evidence for that package existed only as a quoted number in a
handoff (P7 audit conditions A-1 and B-5).

The rule that follows from it, and the one this directory implements:

> **A gate's verdict and its numbers are versioned. The transcript that
> produced them is not.**

## Versioned (here, in git)

* the **verdict block** of each gate run: the PASS/FAIL lines, the
  measured counts, the reference the gate compared against, the
  command, the HEAD and the wall-clock time;
* the **reference families** the byte-neutrality gates compare against
  (`verification/ref_final/`, append-only, with their CAPS words);
* mutation results, because a green gate without its red counter-proof
  says nothing about what the gate can catch;
* the **utilization reports a documented cost number is read from**
  (`*_util_flat.rpt` / `*_util_hier.rpt`). `.gitignore` allows `.rpt`
  under `verification/evidence/**` for exactly this. The reason is a defect that
  happened twice: the documentation named a path in `bld/`, the next run
  of the same script overwrote it with a different configuration, and a
  reader following the reference arrived at numbers that contradicted
  the table (P4 audit B-2, closed by `5293130`; P8 closing audit B-N2,
  the same class one commit later). A cost number whose report is not in
  the tree is a number nobody can check.

## Not versioned (stays in `bld/`, reproducible)

* full `xsim`/`xelab`/`xvlog` transcripts and waveform dumps;
* Vivado checkpoints, logs and the rest of the synthesis run directory;
* SymbiYosys work directories and traces;
* ATB dumps and decoder output.

These are large, machine-specific and regenerated by re-running the
script named in the verdict block. Keeping them would not make the
argument any stronger — keeping the verdict does, because it is the
part a later reader cannot reconstruct once `bld/` has been reused.

## Layout

```
verification/evidence/<package>/<gate>.log
```

Each file starts with a header naming the command, the repository HEAD
and the time, so a verdict can never drift away from what produced it.

## The tools that maintain this tree

Nothing calls these from a script — they are run by hand, once per filed
verdict, which is why a grep for them finds no caller. That is also how
they nearly got deleted as dead code, so they are named here instead.

| Tool | Does |
|---|---|
| [`scripts/keep_evidence.sh`](../../scripts/keep_evidence.sh) | Files a verdict: reads the transcript on stdin, applies an optional grep filter, and writes the `# gate` / `# package` / `# command` / `# HEAD` / `# when` header this directory is checked against. Every log here was produced by it. |
| [`scripts/scrub_evidence_headers.py`](../../scripts/scrub_evidence_headers.py) | Neutralises what a Vivado or gate-script header says about the *machine* — host name to `<host>`, absolute paths cut back to the repository — and leaves the numbers byte-identical. The 52 reports here carrying `<host>` went through it. |

The counterpart guard is `scripts/check_evidence_stamp.py`, below.

## The header contract (checked)

`scripts/check_evidence_stamp.py` runs in `make lint` and CI stage 1 and
holds every `.log` in this tree to it.

| Field | Required | Meaning |
|---|---|---|
| `# gate` | yes | which gate produced the verdict |
| `# package` | yes | which package it belongs to |
| `# command` | yes | how to reproduce it |
| `# HEAD` | yes | the commit it was produced on — **must be in this branch's history** |
| `# when` | yes | date, time and timezone |
| `# covers` | no | paths this verdict claims to be **current** for; red as soon as one of them changes |
| `# superseded-by` | no | another log in this tree that re-ran the same gates on a commit that *is* in the history |
| `# note` | no | free text |

Two of those need a word on why they exist.

**`# HEAD` must be an ancestor.** The P8 fix round filed five verdict
logs stamped `9a41049`. That commit is not on this branch — the worker
had rebased its own commits onto it and never repeated the measurements,
so four P4 commits touching the composer RTL, `ct_pkg.sv`, the formal
runner and the RDL sat between the tree that was measured and the tree
the verdicts were filed against. Nothing in the repository showed it; a
successor found it by taking an inventory by hand. Those six logs now
carry `# superseded-by`, pointing at the run that did repeat them
(`reverify_at_294bf6d.log`), and the guard refuses a supersession by
another orphan — superseding one orphan with another proves nothing. A
superseded log's own stamp may name a commit that was rebased away and is
not an object of a fresh clone at all (that is what `9a41049` is outside
the worker's original clone); the guard accepts that, because the
superseding log is the one that carries the verdict.

**`# covers` is a claim, not a label.** A closed package's evidence is
always older than today's RTL, and failing on that would say nothing.
Declare `covers` while a package still leans on the verdict: the guard
then turns red the moment one of those paths moves, which is precisely
the "is this number still true?" question an auditor asks. Whether it is
declared or not, the guard prints the inventory — age in commits and
which of `rtl/ rdl/ formal/ scripts/ tests/ ci/` moved since — for every
log, on every run.

**The reports a documented number is read from** are held to a matching
rule by `scripts/check_doc_evidence.py`: a doc section quoting CLB LUTs
or flip-flops must name a `.rpt` under `verification/evidence/**`, that file must
exist, and its numbers must be the ones in the table.
