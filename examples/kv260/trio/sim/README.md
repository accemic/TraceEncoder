# `examples/kv260/trio/sim` — simulation leg of the three-core example

One bench, migrated 2026-08-18 from the evidence archive
(`the predecessor repository, package D3b).

`tb_trio_ps_devmem` is `tb_duo_ps_devmem` extended to the third core: it drives
`trio_soc_top`'s AXI4-Lite slave the way Linux `devmem` does, loads `prog.bin`
(MicroBlaze-V) and `prog2.bin` (TGC5B) over AXI and lets the CVA6 fetch from a
64-bit AXI RAM model, arms all three encoders behind the L1 funnel, runs, then
turns tracing off and flushes. Besides the merged ATB capture
(`tb_trio_ps_devmem.atb.bin`) and the three golden PC sequences
(`tb_trio_ps_devmem.core{0,1,2}.retired.pcs`) it carries the D2/T2/U6/U9/U11
gates: DDR-sink accounting, PIB calibration and beat balance, the DDR window
lock plus its read-only property, the per-core start/stop bits and the funnel
tagging.

## It does NOT run on the default backend

Two independent reasons, both structural:

1. `trio_soc_top` instantiates `mbv_soc_synth_wrap` for its MicroBlaze-V
   channel, and that instantiates `mbv_ctrace_soc_wrapper` (generated by
   Vivado's `make_wrapper` from the `mbv_ctrace_soc` block design, around the
   **encrypted** MicroBlaze-V core) plus the Xilinx XPM macro
   `xpm_memory_tdpram`. Neither has an in-repo `.sv` source.
2. The CVA6 channel needs `third_party/cva6_ref`, which is fetched, not
   vendored here — it is fetched by
   [`../../third_party/fetch.sh`](../../third_party/fetch.sh).

The full "what a re-user needs" list is in
[`../../mbv/sim/README.md`](../../mbv/sim/README.md); this bench additionally
needs the fetched CVA6 tree and the two program images (`prog.bin` from
`../../mbv/sw/build/`, `prog2.bin` from the `examples/kv260/common/tgc5b` software),
which the runner places in the simulator work directory under those fixed
names. The CVA6 image is loaded by the RAM model via `+HEX=…`.

Note the bench's own parameter override, carried over from the archive:
`ENC0_ETRACE(0) ENC1_ETRACE(0) ENC2_ETRACE(0)`. The vendored encoder has
`ct_pkg::CT_EN_ETRACE = 0` since the M0 sync, so a DUAL build (the top's
default `1`) trips the `genEtraceNoSideband` elaboration guard. The bench
therefore runs N-Trace-only, and the runner's proto-E leg is dead until
`CT_EN_ETRACE` is re-enabled — a pre-existing condition, not a migration
effect.

## What WAS verified without Vivado

`verilator --lint-only -Wall --timing --top-module tb_trio_ps_devmem` against
the full closure, with three throwaway port-compatible stubs
(`mbv_ctrace_soc_wrapper`, `xpm_memory_tdpram`, `cva6_trace_wrap` — the last
one because the CVA6 core is fetched, not vendored): exit 1
with **zero** real `%Error-` lines (1658 warnings; the only `%Error` line is
the aggregate `Exiting due to N warning(s)`).

Two things that run found, both fixed here:

* the one-shot unit gate instantiated **`ct_soc_trace_buf`**, the archive's
  name for the ring. In this tree the ring is `ct_soc_trace_ring` (migration
  decision A-04) and `examples/kv260/common/tgc5b/rtl/ct_soc_trace_buf.sv` is a
  different, older design that kept the old name. Renamed, with the reason
  written next to the instance.
* the bench's CVA6 memory model `axi_ram_sim` was not part of D3b's declared
  scope (it lived in the archive's `sim/cva6/`), so the bench was incomplete
  without it. It is now [`../../common/sim/axi_ram_sim.sv`](../../common/sim/axi_ram_sim.sv)
  — in `common/sim` rather than here, because any future `cva6_linux`/`cva6_2`
  simulation leg needs the same model.
