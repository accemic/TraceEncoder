# `examples/kv260/mbv/sim` — simulation legs of the MicroBlaze-V example

Migrated 2026-08-18 from the evidence archive (the predecessor repository,
`sim/amd_microblaze_v/` and `sim/board_kv260/`), package D3b. Two of the
archive's three verification levels live here; the third one already moved:

| level | where it lives | how it runs |
|---|---|---|
| adapter unit tests (`tb_mbv_itype_decoder`, `tb_mbv_trap_mapper`, `tb_mbv_to_ctte_tip`) | `rtl/adapters/amd_microblaze_v/test/` | `scripts/cli_adapters_test.sh` (Verilator) |
| encoder probe (`tb_ctte_smoke`) | here | `make sim-ctte-smoke` (Verilator) |
| SoC / end-to-end (everything else here) | here | **Vivado xsim only** — see below |

## Runs on the default backend

```
make sim-ctte-smoke
```

`tb_ctte_smoke` is the encoder alone — no core, no adapter, no Xilinx IP.
It is in `SIM_EXAMPLES`, so `make sim-examples` runs it too. Marker:
`[smoke] PASS`.

## Does NOT run on the default backend — and why

Everything else in this directory instantiates `mbv_ctrace_soc_wrapper`,
either directly or through `mbv_ctte_env` / `mbv_dual_encoder_env` /
`mbv_soc_top`. That module is **generated by Vivado's `make_wrapper` from the
`mbv_ctrace_soc` block design at build time**, around the **encrypted**
MicroBlaze-V core; `mbv_soc_synth_wrap` additionally uses the Xilinx XPM macro
`xpm_memory_tdpram`. Neither has an in-repo `.sv` source, by design — so no
Verilator path can exist for these benches. Measured, not assumed:

```
$ verilator --lint-only --timing --top-module tb_mbv_ps_devmem -f <file list>
%Error-MODMISSING: .../mbv_soc_synth_wrap.sv:132:2: Cannot find file containing module: 'mbv_ctrace_soc_wrapper'
%Error-MODMISSING: .../mbv_soc_synth_wrap.sv:181:2: Cannot find file containing module: 'xpm_memory_tdpram'
%Error: Exiting due to 2 error(s), 509 warning(s)
```

| bench | what it gates | extra it needs beyond a plain project |
|---|---|---|
| `tb_mbv_g0_soc` | G0 baseline: the real core's `TRACE` bus vs. the object-dump oracle | program as COE in the block design |
| `tb_mbv_g4_ctte` (`mbv_ctte_env`) | G4: core → adapter → encoder → ATB carries, and nothing appears before enable | program as COE |
| `tb_mbv_ps_devmem` | G6 stage 1: the whole Linux `devmem` sequence against `mbv_soc_top` | nothing extra (loads its own image over AXI) |
| `tb_mbv_native_probe` | does AMD's own encoder emit anything without a runtime enable? | block design with `MBV_NATIVE_TRACE=1` |
| `tb_mbv_native_enable` | arm AMD's encoder over its private `saxi_*` port, then look again | `MBV_NATIVE_TRACE=1` + the `saxi_*` port |
| `tb_mbv_dual_encoder` (`mbv_dual_encoder_env`, `amd_native_trace_dump`) | two-encoder cross-validation on ONE core | `MBV_NATIVE_TRACE=1` + `saxi_*` |

### What a re-user needs, in order

1. **Vivado** — this tree pins 2022.1 in `.abc.config`; the archive runs used
   2026.1 — and a licence that covers the MicroBlaze-V.
2. Create the project: `../fpga/create_project_kv260.tcl`. It builds the
   `mbv_ctrace_soc` block design and, via `make_wrapper`, writes
   `<proj>.gen/sources_1/bd/mbv_ctrace_soc/hdl/mbv_ctrace_soc_wrapper.v`
   (the TCL names that path at line 127).
3. The tool's XPM library, for `xpm_memory_tdpram`.
4. For the three native-encoder benches, a block-design variant built with
   `MBV_NATIVE_TRACE=1` — only then does the core bring out `dbg_trace_*` and
   its private `saxi_*` register port.
5. For `tb_mbv_g0_soc` / `tb_mbv_g4_ctte`, the program image as a COE inside
   the block design: those two do not load a program themselves (the archive
   rebuilt the BD per test).
6. **`xsim.elaborate.debug_level=off`.** With wave instrumentation the
   xsim 2026.1 kernel dies at time 0 in `ct_L23_preproc_act_proc.sv:64`. That
   is what `tb_ctte_smoke` was written to prove, and it reproduces with the
   bare encoder — it is a tool property, not an integration defect.

Then, from the project, `xelab`/`xsim` the bench you want, or point abc at it
with `abc --sim-backend xsim`.

## What WAS verified here, without Vivado

A skip with no check at all would be worthless: a bench that no longer matches
its DUT after the D2 port rebuild (`ct_trace_sinks`, `m_axi_*`, `pib_*`,
ATB_BP 0x38 → 0x40) would otherwise only be discovered by the next person with
a licence. So every bench in this directory was **elaborated** with the same
recipe the RTL migration used itself — two
throwaway, port-compatible stub modules (`mbv_ctrace_soc_wrapper`,
`xpm_memory_tdpram`) outside the repository, then:

```
export VERILATOR_ROOT="C:/msys64/ucrt64/share/verilator"
verilator --lint-only -Wall --timing --top-module <bench> -f <file list>
```

Result for all six tops: exit 1 with **zero** real `%Error-` lines — the
signature this tree documents for `-Wall` over the full encoder closure (the
only `%Error` line is `Exiting due to N warning(s)`, which is the default
`--error-limit`, not a failure). The hierarchical probes resolve, which is the
part that actually carried risk: `tb_mbv_ps_devmem` reads
`dut.soc.core_trace_pc` / `core_trace_valid`, and the run prints the resolved
path `tb_mbv_ps_devmem.dut.soc.encoder...` in its warnings.

`tb_mbv_ps_devmem` was additionally **adapted** to the D2 rebuild, not just
copied: the two new outward edges are wired (`m_axi_*` to the same minimal
always-ready write-slave model `tb_duo_ps_devmem` uses, mirroring the reset
window `DDR_BASE = 0x5000_0000`; the PIB pins to an observer), and it now
CHECKS the reset-inertness the rebuild claims — it never writes `SINK_CTRL`
(0x18), so the DDR sink must stay silent and `pib_clk` must never toggle.
Note for anyone extending it: **ATB_BP moved from 0x38 to 0x40**; 0x38 is now
the read-only counter `DDR_BEATS` and a write there is swallowed without error.
The register map lives in the header comment of `../rtl/mbv_soc_top.sv` and is
checked against the RTL by `../tools/check_regmap.py`.
