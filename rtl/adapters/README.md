# rtl/adapters -- ingress adapters (core -> CTTE TIP)

One subdirectory per traced core. Each adapter translates that core's
retirement/trap signalling into the CTTE **TIP** (`rtl/pkg/tip_pkg.sv`,
`tip_if`), so the encoder itself stays core-agnostic:

| Directory | Core | Ingress signalling | Specification document |
|---|---|---|---|
| [`amd_microblaze_v/`](amd_microblaze_v/) | AMD MicroBlaze V | the AMD `TRACE` bus (raw signal bundle, vendor-specific) | [`doc/adapters/microblaze_v_trace_semantics.adoc`](../../doc/adapters/microblaze_v_trace_semantics.adoc) |
| [`cva6/`](cva6/) | OpenHW CVA6 | ITI, 3-bit `itype` (needs CALL/RETURN refinement) | [`doc/adapters/cva6_iti_semantics.adoc`](../../doc/adapters/cva6_iti_semantics.adoc) |
| [`rocket/`](rocket/) | rocket-chip | TraceCoreInterface, 4-bit `itype` (full E-Trace vocabulary) | [`doc/adapters/rocket_tci_semantics.adoc`](../../doc/adapters/rocket_tci_semantics.adoc) |

The adapters and their specification documents were migrated into this
repository in 2026-08 from an internal predecessor repository; the RTL
logic is unchanged by that move, and the unit testbenches below are its
re-verification.

## Running the unit gate

```bash
bash scripts/cli_adapters_test.sh
```

The gate drives all six testbenches through `ct_need_prj` +
`xvlog`/`xelab`/`xsim` and checks the SVA error channel (`ct_xsim`), not
just the `PASS` string -- a bench that fails an assertion while printing
`TB_PASS` must not read as green. On a host that has several Vivado
installations next to the pinned one, prefix with `CT_VIVADO_ANY=1` to
relax `ct_need_vivado`'s version check.

`tb_itype_refine_unit` is the one leg that runs with `xelab --debug
typical` instead of the repo-standard `off`. Reason (probed 2026-08-17,
recorded in the runner's own comment): with `--debug off` xelab
mis-schedules the output-port connection of the `cva6_riscv_itype_refine`
instance inside `cva6_iti_to_ctte_tip` -- the instance-internal value is
correct while the sink reads X or lags one clock. Same tool-defect family
as XSIM finding L2 (see `cva6_iti_to_ctte_tip.sv`'s header). The
workaround is pinned on the tool because the instance-internal probe
proves the RTL right.

## Conventions that differ from the rest of the tree

- **Testbench naming.** Elsewhere in `rtl/` the convention is a
  `<module>_tb.sv` *suffix*; the adapter testbenches use a
  `tb_<module>.sv` *prefix* and keep it. `scripts/check_orphan_gates.py`
  deliberately scopes `rtl/adapters/` out of its glob (stated in its own
  docstring: the adapter and board packages have their own runner
  conventions), so neither naming trips that guard -- `cli_adapters_test.sh`
  wires the six benches by name.
- **Stimulus files are read by bare relative name.** `tb_mbv_itype_decoder`
  and `tb_itype_refine_unit` do `$fopen("itype_vectors.vec", ...)`, but
  xsim's working directory at run time is
  `bld/<tb>.abc.vivado/<tb>.abc.sim/sim_1/behav/xsim/`, not the source
  `test/` directory. `cli_adapters_test.sh` therefore copies every
  `test/*.vec` next to the snapshot before starting xsim; without that
  step a fresh checkout fails with a confusing "vector file not found".
  `tb_itype_refine_unit` additionally accepts `+VEC=<path>`.
- **`itype_vectors.vec` are static snapshots.** Both vector files were
  generated by assembler+objdump-based generators (an oracle independent
  of the DUT) that did not migrate with the adapters. Regenerating the
  vector set means porting a generator first; the files themselves are
  checked in and self-describing.

## Known absences (disclosure, not completeness)

- `cva6_trace_wrap.sv` has **no unit testbench here** -- it instantiates the
  vendored CVA6-with-ITI fork by name and cannot elaborate standalone in
  this tree; see [`cva6/README.md`](cva6/README.md).
- The **RV64 variant** of `tb_iti2tip_unit` (a width-parameterized re-run
  plus an XLEN-mismatch probe) was not carried over; RV64
  address-truncation coverage for the CVA6 shim is not in this repository.
- The **SoC-level and native-encoder testbenches** for the MicroBlaze V
  adapter need a real vendored core or drive AMD's competing native
  N-Trace encoder; they are example-level, not adapter-level, material.
- `microblaze_v_native_trace_port` (AMD's native N-Trace port) is
  deliberately not part of `doc/adapters/`: it characterizes a different
  signal path, not the `TRACE`-bus -> TIP adapter implemented here.

## Reading the specification documents

`doc/adapters/microblaze_v_adapter_mapping.adoc` originally restated the
`tip_ecause_e` sentinel as `ECAUSE_NONE = 15`. That value is superseded:
`rtl/pkg/tip_pkg.sv` moved the sentinel to 14 under finding X8a, because 15
collides with the real cause `STORE_PAGE_FAULT` under Sv39 Linux. The
document now points at `tip_pkg.sv` instead of restating a literal. No RTL
is affected -- `mbv_trap_mapper.sv` references `ECAUSE_NONE` symbolically,
never numerically.
